WHAT THIS IS
    An infinite-zoom vector drawing canvas. You draw, you zoom in about 4,096x,
    and you keep drawing at the new scale, for ever. A React app; the whole
    interesting part is a hand-written engine in src/engine/ that renders through
    Two.js into one SVG.

    It is one person's project (Kobin Kempe). There is no team, no CI, no code
    review. Correctness is established by a large Jest suite plus Kobin using the
    app and sending back a diagnostic report. Both matter and neither is
    sufficient - see THE RULES below.

RUN IT
    npm install
    npm start              dev server on :3000   (or the "boundless" launch config)
    npm run report-server  report receiver on :3001, writes .kobin-reports/
    npm run test:quick     everything except *.slow.test.js   (~70 s, 868 tests)
    npm run test:slow      the slow suites            (~500 s, 598 tests)
    npm run test:all       both

    debug overlays, and the Report button).

THE RULES - these are not style preferences, each one cost something
    1.  A GREEN SUITE IS NOT EVIDENCE THAT A CHANGE IS GOOD. The 2026-07-28
        "deep cuts" attempt passed 458 tests and Kobin judged it worse and
        reverted it. Before claiming an improvement to erasing or drawing, get
        his acceptance criteria.
    2.  DO NOT DESCRIBE THE ERASER AS WORKING. Every pass so far has failed in
        real use. State what was measured, not what was intended.
    3.  MEASURE IN A REAL BROWSER FOR ANYTHING ABOUT PAINT. Rasterizing the SVG
        to a canvas CANNOT see the compositing failures (F-Z: three wrong
        diagnoses were talked out of the right answer by canvas measurements).
        Screenshot real Chrome and magnify before calling anything blank.
    4.  A SUITE THAT DOES NOT FINISH IS NOT A SUITE THAT PASSES. Check for the
        summary line, not for the absence of FAIL. Jest once hung for three
        hours on the 63rd of 63 suites with everything reporting PASS.
    5.  AN ODD CROSSING COUNT IS A SYMPTOM, NEVER AN IDENTIFICATION. Two closed
        curves cross an even number of times, so an odd count means something
        is wrong - but F23 and F34 present identically and have different
        causes at different scales.
    6.  PREFER THE ESTIMATOR THAT DEGRADES LOCALLY. Anything that integrates
        along a boundary trades a bounded local error for an unbounded global
        one. This geometry cannot supply the exactness that trade needs.
    7.  DO NOT COMMIT OR PUSH unless asked. Nothing in the current working tree
        is committed (see 10-STATUS.txt).
    8.  WHEN A DESIGN DOCUMENT AND THE CODE DISAGREE, find out which is wrong
        and fix THAT, then say so in the document. Do not leave both standing.

THE ONE THING TO UNDERSTAND BEFORE TOUCHING GEOMETRY
    Every scale problem in this codebase has the same shape: two numbers that
    differ by many orders of magnitude meet in one expression, and the small one
    is destroyed. A tolerance taken from the largest thing in the room. A radius
    squared when the answer is the size of the other radius. A displacement
    multiplied by 4096^k. The fixes always look the same too: keep every small
    quantity small, cancel before you scale, and never let a constant be derived
    from something that varies (the canvas, the camera, the scene).

Context

Selecting things in an infinite canvas

bound.less is a vector drawing surface with no zoom limit. You can draw at one scale, zoom in past several level breaks, and keep drawing at a scale where the earlier marks are thousands of screens wide. Selection has to survive that.

Why the usual answer fails

Every drawing tool marks a selection by outlining its bounding box, and that works because in every other tool the bounding box is roughly screen-sized. Here it is not. The selection rectangle is computed in the coordinates of the frame you are currently looking from, so an object that lives several levels away projects to something enormous — and crucially, that happens because of the depth difference, not because the object is large. A small mark, viewed from far enough in, has an astronomical bounding box.

Once that box is bigger than the screen, it carries no information: all four of its edges are somewhere off in the dark, and what you see is nothing at all. The tool is drawing very hard and showing you nothing.

What it cost

Measured live in a real session on 22 August 2026, after an erase, a move, and a zoom out past a level break:

877,395 px
Width of the selection rectangle, on a 1504 px screen
350,958
Dashes placed per frame, all of them off screen
315 ms
Per frame, against 17 ms with the same box undashed
0.15 ms
Of actual JavaScript — which is why no profiler found it

That last number is the whole story. Dashing a stroke is rasterizer work, so the function that caused a one-second stall reported a sixth of a millisecond of its own time. Five separate root-cause theories were proposed and disproved before the rectangle was measured directly.

The four cases any option must answer

1. On screen
The object fits comfortably in the view. The ordinary case, and the only one existing tools ever have to handle.
Every option works here.
2. Partly off screen
The object runs past an edge. Some of its bounds are visible, some are not.
Most options work; the box starts losing meaning.
3. Huge, partly visible
One edge is barely inside the view and the rest extends far past it. This is what a coarse object looks like from a deep frame.
Where the bounding box became a performance hazard.
4. Covers the view
The object is larger than the screen in every direction. No edge of it is visible anywhere.
A bounding box shows literally nothing here.

The constraint

Bounded work per frame, whatever the zoom

Whatever replaces the box must cost the same at any depth. Anything proportional to the selection's projected size — a stroked perimeter, a dash pattern, a path that leaves the viewport — reintroduces the same failure in a new shape. In practice this means clipping to the viewport before stroking, animating opacity rather than geometry, and preferring a fixed number of marks over an outline whose length depends on the object.

Where it stands

A placeholder guard now ships in Renderer.selectionDrawable(): the outline is drawn only when it overlaps the viewport and is at most three viewports across. Both conditions mean “there is something to look at”. Cases 3 and 4 therefore show no selection indicator at all right now — deliberately, as a stopgap. The options in the Selection group are the candidates to replace it.
